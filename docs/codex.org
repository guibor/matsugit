#+title: matsugit in Codex

* Present
Click the presentation-screen icon at the top right. It switches to slides and
hides the editor and workspace chrome. Use arrow keys, Space, Page Up/Down or the
quiet bottom-right controls. Escape or the exit icon restores your previous view
and Sync setting. Browser fullscreen is requested when allowed; embedded hosts
that block it still get the full slide-only workspace. Nothing is saved or published.

Upgrade the plugin, then open the document in a fresh Codex session:
#+begin_src sh
codex plugin marketplace upgrade matsugit
codex plugin add matsugit@matsugit
#+end_src

* Install

Upgrading from Folioforge? Follow [[file:migration.org][the rename migration guide]] first;
the new plugin identity is =matsugit@matsugit=. Save drafts before removing an old viewer.

This is a local MCP App plugin, not a hosted editor. Install on the machine
where Codex can read the source files. It requires Node 22+, Python 3.10+,
Git and Quarto on the Codex process's PATH. The renderer is included; a separate
pip install of matsugit is not required. Chart preparation still needs
matsugit's optional chart environment.

#+begin_src sh
codex plugin marketplace add guibor/matsugit
codex plugin add matsugit@matsugit
#+end_src

The repository currently requires authorized Git access. These commands neither
change repository visibility nor publish documents. For a local checkout, use
its absolute path in the first command instead of =guibor/matsugit=.
Start a new Codex session after installation. Use Codex's plugin manager to
refresh an installed plugin after a release; the plugin cache is separate from
your ordinary source checkout, so a checkout's =git pull= alone does not update
that cache.

To update this Git-backed marketplace and install its current plugin version,
run from an existing directory (not inside the plugin cache):
#+begin_src sh
cd "$HOME"
codex plugin marketplace upgrade matsugit
codex plugin add matsugit@matsugit
#+end_src
Save or download unsaved workspace text first, then reload the plugin or restart
Codex to stop using the old MCP process. From 0.3.1, an already-running workspace
retains its own renderer when an update replaces the installed cache. It continues
using that version until reloaded, rather than switching code under a draft.
This does not require reinstalling Python, pyenv, Quarto or Emacs.

The interactive workspace needs Codex Desktop with MCP Apps support. File
handlers need a desktop build supporting OpenAI Extensions file entrypoints;
the CLI alone cannot display the workspace. If the file action is absent, ask
the agent to open the file through =matsugit_open=. This still requires an
MCP Apps-capable UI, and is not a workaround for a terminal-only host.

* Open and work

Plugin 0.14.2 adds a real =Theme= dropdown, populated from the active machine's
configured =themes_dir= before rendering. It includes inherited theme packs and
the built-in =default= theme. The first item follows the document/project default;
choosing another theme affects this workspace, not the source or machine default.
=Refresh= also rescans installed themes. Discovery does not need Quarto and does
not install themes, publish, or send their files to a service.

With plugin 0.14.1+, the workspace's own save endpoint does not rewrite a file
when the content is unchanged. This preserves its inode and modification time
for editors such as Emacs. Revision checks still run first; an obsolete revision
cannot bypass a real conflict. Host-managed file handlers control their own
write behavior, and other programs can still rewrite the source independently.

Ask Codex: "Open /absolute/path/deck.md in matsugit with a split slide preview."
Alternatively choose the matsugit action for a supported file in Codex, or
open the global matsugit workspace to start an unsaved draft.

- =Markdown=: source only, with highlighting, undo, search and line wrapping.
- =Story=: a full-width narrative editor; optional Preview sits alongside it.
- =Render=: preview only.
- =Split=: source and preview, with a draggable/keyboard-resizable divider.
- =Document= / =Slides=: choose the rendered output independently of layout.
- The selected slide is retained across preview refreshes when it still exists.
- =Auto=: render after a pause in editing. Refresh first checks the file for
  external changes, then renders the latest source even with Auto off. Unsaved
  text or table edits are retained on conflict; no automatic overwrite occurs.
  A spinner, completion checkmark and brief notification acknowledge the action.
  Shift-click the refresh icon to force a complete rebuild of the selected view.
- =Sync=: follow the edited heading in the document/slide preview, and follow
  preview navigation back to its source heading. Turn it off to browse panes
  independently. Matching uses heading text and hierarchy, not guessed pixels;
  body paragraphs follow their containing heading, not an exact scroll fraction.
- =Theme=: choose the first item to follow project defaults, or an installed
  theme to try it for this preview. This does not change your source or settings.
- Save icon or =Ctrl/Cmd-S=: save explicitly. Rendering never saves the source.
- Download icon: download the current source, including unsaved edits.

The renderer supports Markdown, Quarto Markdown and Org. The editor currently
provides Markdown highlighting; Org source still renders through matsugit's
native conversion path. Existing source-relative images work when a repository
file is opened. The file-picker button imports a browser copy: it has no
write-back permission or access to adjacent assets. Download that copy, or open
the actual repository file through Codex.

** Story: overview and walkthrough (0.18)

Choose =Story= in the top view switch, then choose a presentation of the narrative:

- =Overview= (default): a dense outline, with section bands, indented slides and
  title/claim pairs. Wider windows place each pair side by side; narrower panes
  put the claim beneath its title. Fold sections to inspect the larger structure.
- =Walkthrough=: scroll through slide-shaped surfaces showing only the editable
  title, claim and takeaways, with section context and slide numbers. There is no evidence
  body here, even when the real slide has one. Previous/next buttons and
  =PageUp= / =PageDown= scroll without selecting, or step through selected slides.

Switching keeps your place and never changes source or adds an Undo step.
Walkthrough shows all slides, including those folded in Overview. Returning
to Overview reveals the section containing the current slide. The presentation
choice is retained in workspace recovery. There are no separate title/claim tabs.
Preview is off initially, avoiding a render after every edit while you work on the story.
Enable =Preview= for the existing Document/Slides output and heading synchronization.

Plugin 0.20 adds the *sparkles* icon on every slide in both Story views.
Click =Edit slide with AI=, enter instructions, inspect =Slide source= if needed,
then =Send=. The request goes to the current host conversation, not a new agent
or model. =Save and send= first saves *all current document edits* using the
normal version checks. A failed save or concurrent file change prevents sending.
Only the selected H2 subtree plus its path, version and location is attached;
other slides and the preamble are not included. Manual continuations belong to
that subtree. The agent is asked to check the current file before a targeted edit.
Subsequent agent edits still use the existing external-change/merge review.

The action requires a saved local file and a host advertising chat messaging.
Without that capability, =Copy request= provides the scoped request instead;
it neither saves nor sends. Unsaved imported documents must first be saved and
opened as actual local files. Closing an unsubmitted prompt retains its text
for that slide while this workspace remains open. If delivery is unconfirmed,
check the chat first: matsugit does not retry automatically. A successful send
confirms delivery, not completion of the agent's work. Nothing is published.

- Click a section title, slide title or claim to edit it in place. Tab / Shift-Tab
  move between narrative fields, including the paired title and claim. Enter or
  Escape ends editing, retaining your draft edits. Inline Markdown is visible
  while editing; stable heading IDs/classes and Org tags/properties stay intact.
- Takeaways appear beneath the title/claim in both views. Single-line fenced
  Markdown, =[!TAKEAWAY]= callouts and native Org takeaways can be edited inline.
  Multiline takeaways remain visible; click one to edit at its source location.
  Notes, source blocks and agent comments are not exposed as takeaways.
- With nothing selected, =Up= / =Down=, =Left= / =Right= and =k= / =j= scroll.
  =PageUp= / =PageDown= scroll a viewport; =Home= / =End= go to the ends.
  =h= / =l= visit the previous/next section. They never select or reorder text.
  Click a row's number/background, or Tab to a row, to select it. Then the
  same keys move selection instead (Page keys step slides in Walkthrough).
  Escape or clicking outside the rows clears selection. Wheel/trackpad scrolling
  leaves an existing selection where it was. None of these keys intercepts
  typing or caret movement in a field, form, dialog, source editor or presentation.
- Drag by the grip, or use up/down arrows to move among siblings. =Alt-Up= /
  =Alt-Down= work on a focused row. Enter edits the focused title.
- Move a slide between sections with the two-way arrow, or drop its grip on a
  section title. The destination selector appends it to that section. Dropping
  on another slide inserts before/after the highlighted boundary.
- A section carries all of its slides. A slide carries all text through the
  next H1/H2 boundary, including evidence, H3/H4 headings, notes and comments.
  Claims can be edited independently but are not detached from their slide.
- =Add slide= asks for a title and optional claim, then inserts the new slide
  after the selected slide, with an *empty body*. No evidence, placeholder bullets
  or agent request is invented. =Empty body= identifies slides awaiting detail.
  Save, then ask your agent to develop those slides without changing their order
  or claims. The folder-plus adds a section. A slide without a claim offers =+ Claim=.
- In Overview, the chevron or Space on a focused section folds/unfolds it.
  The code icon returns to that heading in the regular source editor.
- =Ctrl/Cmd-Z= and =Ctrl/Cmd-Shift-Z= undo/redo. Each move is one Undo step.
  Edits enter the same draft immediately; only Save writes the file.

This follows the H1 section / H2 slide / H3 claim source convention in Markdown
and native Org. It is not a thumbnail sorter for renderer-generated overflow
slides. Manual =---= continuations move with their H2 title, with a continuation
count in Story. Preamble/YAML stays in place, including a leading blank line or
BOM. HTML authoring comments and their examples do not become slides or blocks.
No source serialization or HTML round trip is involved. Single-line explicit
=claim= blocks are paired and editable too. Bodies, multiline claim blocks and
multiline Setext titles remain editable through the source icon.
Changing a heading's implicit anchor has the same effect as editing it in Raw;
use explicit heading IDs for links that must survive renaming.

Moves are refused when unfinished blocks would change the parse. Incoming agent
edits use the same merge/review protections as Raw/Visual. A title is never a
separate unsaved form: recovery and Save see its current text. No file is saved,
published or sent to an agent simply by rearranging the story.

** External change review and publication status (0.15)

The =Review latest external changes= comparison button opens the latest external
edit, grouped by slide/section headings. Each changed block shows Before and
External edit. Leave its checkbox selected to accept it; clear it to reject it.
=Preview merge= computes the resulting draft, invoking the existing conflict
resolver for overlaps. =Apply to draft= preserves a recovery copy and checks
the current file version again. It never saves automatically.

This also works after a clean automatic merge. Rejecting an agent change is
rebased over later independent typing; overlaps still need a decision. The
review record is for the latest external revision in this open viewer, not a
persistent Git history. Opening another file clears it. Recovery copies remain
available separately.

The publication button reads a local receipt on opening a file, without a network
request. It shows =Not pushed=, =Changes not pushed=, =Pushed=, =Building=,
=CI failed= or =Published=. Save status stays separate. Click for the target,
pushed/deployed revisions and pipeline link; use its refresh icon to explicitly
query GitHub/GitLab with existing =gh= / =glab= authentication. This never logs in,
pushes, starts CI or changes permissions. See [[file:delivery.org][verification limits]].

Receipts track publication through this workspace, not arbitrary command-line
pushes. Matching is based on the opened source's contents; changing a referenced
asset separately still requires republishing. Cached deployment results show
their last check time and are not a continuous availability monitor.

** Source hints and insertion

The source remains normal editable text. Subtle line colours and gutter markers
identify sections (=S=), slide titles (=T=), claims (=C=), body regions (=R=),
takeaways (=!=) and agent reviews (=A=). Hover a marker for its name. Markdown
semantic blocks have matching start/end handles and can be folded with the
editor's fold gutter. Code examples are not interpreted as slide structure.
These heading roles describe =slide-layout: structured=; they do not silently
change the layout setting of an existing document.

Type =/= at the start of a blank source line, then choose an insertion, or use
the =+= toolbar button. Filter by typing, choose with the arrow keys and Enter,
and dismiss with Escape. This inserts source locally; it is not a Codex chat
slash command, does not call an agent, and does not save or publish.

| Insert | Purpose |
|--------+---------|
| =/slide=, =/section=, =/claim=, =/region= | Heading hierarchy |
| =/columns=, =/columns-3=, =/rows= | Explicit supporting-content layout |
| =/takeaway=, =/source=, =/notes= | Conclusion, citation, presenter notes |
| =/table-block= | Small editable Markdown table |
| =/break= | Explicit slide break |
| =/agent-comment= | Hidden review request with a fresh stable ID |
| =/metrics=, =/comparison=, =/mapping=, =/implication= | Complete slide recipes |
| =/evidence=, =/annotated=, =/chart= | Evidence and diagram recipes |

The complete menu also includes the other =matsugit template= recipes. They
come from the same Python catalogue, not an independent copy of the syntax.
In an Org file, insertions use native Org headings and blocks. Each insertion
can be undone. The menu avoids Markdown code fences and hidden review bodies.

** Theme defaults

Explicit preview overrides win over the nearest project's =matsugit.json=,
then user settings in =~/.config/matsugit/config.json=, then the built-in
default. For example, set =theme= and =themes_dir= in that JSON file to use a
trusted local theme pack. A theme in a shell wrapper alone is not inherited by
an already-running Codex desktop process. Project settings remain authoritative;
changing the machine default does not override an explicit project choice.

* Saving and concurrent edits

Plugin 0.14.3 shows file state beside the filename: =Unsaved=, =Saving...=,
=Saved=, =Not saved= or =Review changes=. Hover for the last save time or the
failure reason. =Table edits= means a table draft still needs applying. A local
import without a writable file connection is labeled =Local copy= or =Unsaved
copy=. The footer's =Recovery saved= means a backup only, not a file save.

Host-selected files use Codex resource permissions and version tokens. Files
opened through =matsugit_open= use opaque sessions scoped to the selected
file, SHA-256 version checks and an atomic replacement. Saving requires the
version originally read; the plugin does not offer force overwrite.

When an agent or editor changes a file, a clean workspace reloads it. Plugin
0.14.2 uses a three-way merge for independent edits in a dirty workspace, with
the last shared file as the base. It retains a separate pre-merge recovery copy,
merges into the draft, and leaves Save to you. Identical edits are not duplicated.
It does not guess how to combine changes to the same lines.

For overlapping changes choose =Review changes=, then =Merge changes=. Each
conflict shows your draft and the file side by side, with an expandable common
base. Choose =Use mine=, =Use file=, =Keep both=, or edit the resolution. Navigate
with the arrow buttons or =Alt-Left/Right=. =Apply to draft= requires all conflicts
to be resolved and rechecks the incoming file version. Save remains separate.
Cancel leaves both versions untouched. Ordinary typing is never a review shortcut.

Undo after a merge returns to the incoming file, not the old version without the
agent's edits; Redo restores the merged draft. The full pre-merge text remains in
recovery. Pending table edits, an active Redo branch, different documents, a failed
backup or a newer file during review prevent automatic replacement. Apply/cancel
table edits first. Large or expensive merges run in a bounded background worker;
a timeout retains both versions for manual review or external merging.
Both file-entrypoint and tool-opened workspaces poll for changes every three
seconds, in addition to supported host notifications. Superseded renders are
canceled; they cannot replace a newer preview. Clicking refresh during a render
queues the latest draft, including when =Auto= is off.
The existing =Use incoming file= action also preserves a separate draft backup.
The text editor uses UTF-8 and may normalize line endings when you explicitly save.
Version 0.4.0 checkpoints drafts separately from Save, as described below.
Save or download before intentional upgrades and closing important work. Neither
an unload warning nor a final asynchronous checkpoint is guaranteed on host exit.

Agent edits through the workspace's model-context tools target the current draft
with an expected revision, not a stale disk copy. They do not save or publish.
If the host does not expose these tools, coordinate disk edits with the user
rather than overwriting an unsaved draft.

* Draft recovery and workspace restoration (0.4.0+)

Editing automatically checkpoints the current text, its original file baseline,
theme override, Document/Slides selection, source/render/split/story layout, story
detail and preview selection, split size,
caret/selection, editor scroll and preview position. Checkpoints run after 600 ms
of inactivity, with a two-second flush while editing continuously. The footer
reports =Recovery pending=, =Recovery saved= or =Recovery unavailable=; hover it
for the timestamp or failure reason. These are best-effort timings, not a promise
that keystrokes typed immediately before a crash can be recovered.

Reopen the same file in matsugit. View settings return automatically; an
unsaved draft is offered with =Restore draft= and =Not now=. Restoring does not
write the file. If it changed elsewhere, use =Review changes= to merge the
draft, or explicitly use the latest file. =Not now= leaves the
older recovery copy in the history list. If an agent saved exactly the recovered
text, it is recognized as already saved.

The history icon (=Recover workspaces=) lists copies for the current document.
Open the global matsugit workspace to browse all local copies, including
unnamed drafts and files that no longer exist. Missing files recover as
downloadable drafts; the plugin does not recreate a deleted source silently.
Each viewer gets its own copy, so two open viewers cannot overwrite each other's
recovery record. Delete unwanted copies explicitly using the trash icon; deleting
the currently active copy pauses checkpoints for that viewer until reopened.

Storage is on the machine running the plugin server, outside the plugin cache:

- macOS: =~/Library/Application Support/matsugit/recovery=.
- Linux: =$XDG_STATE_HOME/matsugit/recovery=, normally
  =~/.local/state/matsugit/recovery=.
- =MATSUGIT_RECOVERY_DIR= overrides the directory when set in the MCP server's
  environment. Do not select a shared or public directory.

Records are plaintext UTF-8 JSON, not encrypted. On macOS/Linux the directory
must be private to the current user (0700), and records are created with 0600
permissions. They contain source text, a baseline and view settings, not rendered
HTML or copied theme packs. No credentials are collected; confidential material
already in the source is necessarily present in its recovery copy. Writes use a synced temporary file and
atomic replacement. Invalid copies are retained and reported, not discarded.
An interrupted record lock can block further writes to that copy; reopen the
workspace to create a fresh writer and recover the intact prior copy.

Limits: 128 copies and 128 MiB per storage directory, with the existing 2 MiB
source limit. A full directory stops checkpoints with an explicit error; it does
not evict unsaved work. Remove old copies in the picker after keeping what you
need. This is local recovery, not cloud sync, unlimited undo history, or automatic
restoration of every Codex window. The first preview after reopening is rebuilt.
Opaque host resource URIs remain host-controlled; reopening that file through
the host is required to reconnect saving. Generic recovery can retain its text
without inventing a local path or gaining new file permissions.

* Rendering boundaries

** Smart refresh

Only the selected Document or Slides view is rendered. The other view is
updated when selected; switching to an already-current view reuses its HTML.
After the first full render, ordinary prose, emphasis, link, list-item and
table-cell edits update their text regions in place. Unchanged slides, diagrams,
images, fonts and compiled theme styles stay loaded. The current slide and
scroll position are preserved; source/preview following remains controlled by
=Sync=.

This is deliberately not a second, approximate Markdown renderer. The complete
source is reparsed with Quarto's bundled Pandoc, shared references are resolved,
and the usual matsugit conversions run. Only inert inline regions with
unchanged surrounding structure qualify for patches. Headings (including TOC
and menu dependencies), YAML, inserted/deleted blocks, table geometry, code,
math, diagrams, images and theme changes take the full-render path. Merged-table
edits currently use that path too. A patch with the wrong base revision or a
missing DOM target falls back to a rebuild, never a partial stale update.

Chart generation is cached by its parsed data, theme palette and available
width within the preview history. Local asset content and resolved theme files
are checked on every refresh. A remote image changed at the same URL cannot be
detected from the source alone; use Shift-refresh to rebuild it. Temporary
preview history is bounded and is removed when the plugin process closes.

Exports and CI continue to use the authoritative full renderer. They contain
no preview anchors and do not depend on the editor cache. The first render and
structural rebuilds still take longer than warm text edits. The cache is not
crash recovery and never saves the source file.

** Worker execution

Rendering uses a temporary directory, the existing matsugit parser and
trusted local themes. Document code is not executed. Project configuration may
select a theme, but cannot select an executable for the plugin worker: Quarto
comes from PATH or the explicit =QUARTO= environment variable.
=MATSUGIT_PYTHON= can select the Python executable at plugin launch.
Each Python worker starts in its own temporary render directory with a matching
=PWD=, never the host's inherited working directory. Source-relative assets and
project settings still resolve against the explicitly opened source file.

** Plugin cache replacement

Before 0.3.1, a running MCP process read its Python worker and UI from the
installed plugin directory on every use. If a plugin update or cache cleanup
removed that directory while the process stayed alive, preview reported
"matsugit plugin files are no longer available". That warning concerns the
plugin installation, not the user's source document.

Version 0.3.1 embeds the UI and a version-matched renderer payload in the server
bundle. A running process materializes its renderer into a private, process-owned
temporary directory. Removing or replacing the installed cache does not affect
its UI, worker imports, default theme or renderer assets. If that temporary
runtime is removed or modified, it is recreated from the same in-memory payload;
the plugin never searches for another installed version or downloads code.
External themes, source-relative assets, Python and Quarto remain external.

Only bundled program files go into this runtime, not source documents, credentials
or private themes. It is removed on normal process exit; an abrupt OS termination
can leave temporary program files for normal OS cleanup. Existing preview jobs
retain their own lifecycle. This is runtime protection, not draft crash recovery.

Older already-running processes cannot acquire this fix without a reload. Save
or download their unsaved text before updating/reloading. Do not delete a cache
manually, force-kill a session, or reinstall Python to repair this condition.

** Deleted working directory

=shell-init: error retrieving current directory= followed by
=pyenv: cannot change working directory= means a process retained a directory
that was removed. Version =0.1.2= fixes this in the preview worker. It also gives
a reload instruction if the plugin files themselves disappeared; version =0.3.1=
adds the cache-replacement protection described above. The editor text is retained
after a failed render. Save or download it before restarting Codex.

If the error occurs in Terminal, =cd "$HOME"= repairs that shell's current
directory before updating. If it happens before matsugit's tools load, use
an existing project directory and restart Codex; a plugin cannot repair the
parent host's working directory before its own process has started.

** Preview isolation

The document and slide HTML run in a separate opaque-origin sandbox iframe.
An inert =https://matsugit.invalid/= base lets Reveal resolve its embedded menu
URLs inside a blob document; it grants no network connection to that domain.
The plugin has no HTTP listener or deployment tool. Source text and rendered
HTML are carried in app-only MCP metadata rather than echoed into the tool's
model-facing result. This is not a promise that Codex cannot read a file when
the user asks the agent to edit it.

The initial limits are 2 MiB of source, two concurrent renders, four minutes
per render and 20 MiB of embedded HTML per output. A failed render retains the
last successful preview and the editor text. Preview links switch between
document and slides; external navigation is disabled inside the preview frame.

* Raw and Visual editing (0.10.0+)

Choose =Raw= or =Visual= above the source pane, independently of the
=Document= / =Slides= preview. Raw retains the full Markdown source. Visual
styles headings, emphasis and links, revealing inline syntax at the cursor,
and shows pipe/grid tables as tables. Switching modes never rewrites the source.
Custom slide blocks, YAML, code and unsupported constructs remain source-backed;
this is not a general HTML-to-Markdown round trip. Raw is the initial default;
the choice is remembered per recovered workspace.

Click a table cell to edit in place, or use its pencil. Expand opens a larger
editor without discarding your draft. In Raw, put the cursor in a table and use
the table icon or =Alt-.=. The embedded editor uses the same Tiptap/ProseMirror
schema and validated Pandoc conversion as =matsugit edit-table=. It supports
formatting, links, row/column operations, merge/split and local undo/redo.
Tab/Shift-Tab move between cells; select entire rows/columns and align columns
from the toolbar. Paste a spreadsheet's tab-separated cells directly into the
grid, including quoted multiline values. Formulas stay literal text; they never
execute. Oversized pastes are rejected without replacing the current selection.
Rendered Document/Slides previews stay output-only; edit in the source pane's
Visual view or the table editor, not in the output iframe.
=Apply= makes one undoable source change; it does not save the document.
Simple tables remain pipe Markdown; merged/multiline cells use Pandoc grid
Markdown, never a replacement block of HTML. =Save= remains explicit.

Unapplied table edits are included in private recovery checkpoints. If the source
changes while the table is open, Apply refuses to overwrite it: download the
table draft and reopen the current table to reconcile. Closing an edited table
asks before discarding. Cmd/Ctrl-S inside the table dialog applies it; use Save
afterward to write the document.

The visual source display bounds pipe tables to 250 rows/1000 cells; larger
tables stay raw, with no lost rows. Conversion supports up to 500 rows/4000 cells
and 1 MiB. Unsupported table content, such as images or math, fails with source
unchanged rather than silently dropping it. Full-prose Visual mode is Markdown
only for now; native Org tables can still use the table icon. Org formula tables
stay with native Org tools.

The copy icon beside the filename copies the canonical local document path.
Unnamed/browser-imported drafts have no local path; an opaque host resource
works only when the host supplies its real path. No path is guessed from its name.

* Develop and verify

The committed =codex-plugin/bundle/= contains the actual runtime and UI; users
do not run npm during plugin installation. After changing source:

Rebuild after changing Python renderer modules, =worker.py=, the bundled default
theme or runtime CSS/JS too: these are now embedded in =server.mjs=. The cache
removal tests check the bundled payload against the current source files.

Building also requires Python and Pandoc (or Quarto's Pandoc) to generate the
shared Markdown/Org insertion catalogue. No conversion runs on each keystroke.

#+begin_src sh
cd codex-plugin
npm ci
npm run build
npm test
QUARTO=/path/to/quarto node --test tests/cache-render.test.mjs
QUARTO=/path/to/quarto /path/to/playwright-python tests/browser.py
QUARTO=/path/to/quarto /path/to/playwright-python tests/recovery-browser.py
#+end_src

Set =PLAYWRIGHT_CHROMIUM_EXECUTABLE= when using an existing Chromium binary.
The browser test uses an isolated loopback host, real stdio MCP and a synthetic
deck. It checks layouts, rendering, editing, saving, conflict retention and the
file-handler resource flow. It does not publish or open personal files.
The recovery suite restarts a disposable MCP server, restores draft/view state,
checks independent viewers and external edits, exercises the recovery picker at
desktop/mobile widths, and verifies host-resource saving and checkpoint failures.
Also run =python3 -m unittest discover -s tests= from the repository root.

Passing protocol/browser tests does not prove integration in every Codex Desktop
release. Check installation, tool discovery and opening/saving a synthetic file
in the actual target desktop before relying on it for important unsaved work.
* Less layout syntax

Type =/columns= to see equal, evidence/commentary and three-column choices.
=/columns-evidence= inserts =:::: columns 2:1= with H4 region headings.
=/takeaway= inserts a quoted =[!TAKEAWAY]= callout. Long-form source still works.
New placeholder fields use =Tab= and =Shift-Tab=; press =Escape= to leave them.

Select a pipe table, click =+=, and choose =/chart-barh=, =/chart-bar=,
=/chart-line=, =/chart-stacked= or =/chart-stacked100=. This wraps the table rather
than making a second copy. Set its =unit= to the real measurement unit. The
=/chart-slide= recipe creates a complete slide. Type =/chart= to choose a chart
element type. Selected prose can be
wrapped through =/takeaway=. Unsupported selections are retained with an error.

a ratio selector for titled regions without explicit widths. Ratio changes are
ordinary undoable source edits. Markdown and native Org share these controls.
