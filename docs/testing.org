#+title: Renderer and workspace regression checks

* Fast checks
#+begin_src sh
npm ci --prefix codex-plugin
npm run build --prefix codex-plugin
npm test --prefix codex-plugin
QUARTO= python3 -m unittest discover -s tests
#+end_src

Node 22+, Python 3.10+ and a span-aware Pandoc are required. The empty QUARTO
setting skips optional heavyweight rendering tests; converter discovery still
uses installed Pandoc/Quarto. =matsugit setup-editor= explicitly provisions the
isolated converter when needed.

* Local / preview / CI parity
#+begin_src sh
MATSUGIT_PARITY_RENDER=1 python3 -m unittest discover -s tests -p test_render_parity.py -v
#+end_src

The fast contract covers Markdown and native Org, sources and reading-note
visibility both on/off, built-in and synthetic themes, columns, tables, claims,
quotes, takeaways and literal syntax examples. It compares generated inputs and
theme/runtime files against a freshly installed native CI renderer.

The opt-in check renders real HTML through local export, the plugin preview
engine and the actual installed CI entrypoint. It verifies visible content and
embedded CSS with Quarto's bundled Pandoc, including older readers that ignore
Org BEGIN-block parameters. The test uses only synthetic content and never
publishes, pushes, authenticates, or changes an existing CI checkout.

This checks the native matsugit CI bundle, not every third-party or older private
renderer. The =topics= adapter intentionally uses the destination's own renderer;
updating the plugin cannot silently update that separate deployment.

* Browser safety
#+begin_src sh
python3 -m pip install playwright
python3 -m playwright install chromium
python3 codex-plugin/tests/merge-browser.py
python3 codex-plugin/tests/review-status-browser.py
python3 codex-plugin/tests/story-browser.py
python3 codex-plugin/tests/story-navigation-browser.py
python3 codex-plugin/tests/story-layout-browser.py
python3 codex-plugin/tests/slide-agent-browser.py
python3 codex-plugin/tests/check-browser.py
#+end_src

The browser tests exercise the real built MCP workspace with temporary synthetic
files: concurrent drafts, recovery-copy failures, stale versions, selective
review, conflict choices, explicit saving, publication receipts and narrow/wide
viewports. Story tests cover subtree moves, drag/drop, keyboard reordering, title
edits, section/detail folding, explicit saves, undo and concurrent agent edits.
Layout tests cover section transitions, compact grid traversal, persistent size
preferences, empty sections, long titles, native Org and mobile/split panes.
The check test makes beginner mistakes in a draft and covers the verdict chip,
located findings, Show, a fix with Undo, the Ask AI prefill, the stale-preview
marker and where the layout picker puts a slide or part; the file is never saved.
=npm test= also runs every reported problem through the real renderer, which
must fail or misrender where the check says so and accept each fixed text.
Slide AI tests use a local mock chat host, never a real agent. They check both
messaging capabilities, selected-slide scope, Save and send, stale-draft refusal,
uncertain delivery without retry, prompt retention and unsupported-host copying.
Provider status tests mock GitHub/GitLab responses; real deployment
access is not required. =ci/checks.yml= is the reviewed GitHub Actions recipe for
pushes to main, pull requests and manual dispatch. It checks dependency
advisories for all three npm lockfiles and builds complete bundled license
notices. Missing notice text fails the build, including the Story CLI graph.
History is scanned locally on the runner with a checksum-pinned Gitleaks binary;
findings are redacted and source is not sent to a scanning service. npm audit
sends dependency names/versions to the npm registry, not document contents.
This is test CI for this repository, not a deployment workflow for user documents.
No account scopes are requested or expanded by matsugit.

*CI is not active until a maintainer installs this recipe.* The credential used
for the cleanup lacked GitHub's =workflow= scope. From a clean checkout, with
workflow-authorized credentials:
#+begin_src sh
mkdir -p .github/workflows
git mv ci/checks.yml .github/workflows/checks.yml
git commit -m "Activate repository checks"
git push
#+end_src
For GitHub CLI OAuth, =gh auth refresh -h github.com -s workflow= requests that
additional scope interactively. This is an explicit maintainer decision, not a
step performed by plugin installation. Verify the first Actions run after push.

Plugin 0.25.1 overrides the exact Zod pin in =@openai/mcp-extensions= 0.2.1
with the project's patched Zod 4 dependency. See
[[https://github.com/advisories/GHSA-mrhx-c7xc-m3w5][GHSA-mrhx-c7xc-m3w5]].
The lockfile resolves 4.6.7; the minimum is 4.6.6. Remove the scoped override
when upstream accepts a patched version, after rerunning the protocol tests.
An advisory scan checks published advisories, not every possible security flaw.

The optional =MATSUGIT_ORG_PREVIEWS= browser corpus uses directories named
=md-theme-a=, =org-theme-a= and =org-theme-b=. The first two must be equivalent
Markdown/Org renders; the third tests a second theme. Keep private theme assets
and real documents outside this repository.
