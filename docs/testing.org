#+title: Renderer and workspace regression checks

* Robustness tests (0.30)
#+begin_src sh
python3 codex-plugin/tests/concurrency-fuzz-browser.py
python3 codex-plugin/tests/controls-audit-browser.py
python3 codex-plugin/tests/file-trouble-browser.py
#+end_src
- =concurrency-fuzz-browser.py= is a seeded stress test: the author types,
  amends, undoes and saves (autosave on and off) while another writer makes
  targeted edits, rewrites from an older read and changes the same lines. Every
  line carries a marker; the test fails if the workspace ever removes another
  writer's line from the file, loses the author's typing, raises a page error or
  stays busy. Reviews are resolved with "Keep both". Choose runs with
  =MATSUGIT_FUZZ_SEEDS=1,2,3= and =MATSUGIT_FUZZ_STEPS=30=.
- =controls-audit-browser.py= clicks every visible, enabled control in five
  states (saved file, unsaved draft, Story, untitled workspace, Cursor panel)
  and fails on one that does nothing, a disabled one without a reason, a page
  error, or a file write without Save.
- =file-trouble-browser.py= covers a plugin restart, a read-only file, a
  deleted file, a moved file and two windows on one file.
Each also runs in the Cursor-style host with =MATSUGIT_TEST_HOST=cursor
MATSUGIT_STANDARD_MCP=1=.

* Package size

=tests/test_package_size.py= reports the 8 MB (8,000,000 bytes) secondary target
and lists the largest files when exceeded. Reliability and functionality take
priority. Set =MATSUGIT_ENFORCE_SIZE_LIMIT=1= only for a distribution with a hard
upload limit. This is a source-tree measurement,
not a measurement of downstream ZIPs: those can include themes, review evidence
and older renderer releases. Measure their expanded payload separately.
What keeps this tree small:
- Dependency lockfiles use compact JSON. This changes whitespace only, not
  versions, integrity hashes or dependency metadata. After regenerating them:
  =node -e 'const fs=require("fs"); for(const p of ["codex-plugin/package-lock.json","editor/package-lock.json"]) fs.writeFileSync(p,JSON.stringify(JSON.parse(fs.readFileSync(p,"utf8")))+"\n")'=
- The merge worker is embedded in the server runtime, which extracts it before
  use. There is no redundant =bundle/merge-worker.cjs=; the internal review ZIP
  extracts a readable copy from that same runtime.
- The workspace page is not committed separately: it lives inside
  =codex-plugin/bundle/server.mjs=. =node codex-plugin/app-html.mjs > app.html=
  writes it out for inspection; tests and the demo read it the same way.
- MathJax is stored as =matsugit/runtime/mathjax-tex-svg.js.gz=. Rendering
  (=core.expand_runtime=), CI setup and the plugin bundle write out the plain
  file; =tests/test_math.py= checks the expanded bytes against the reviewed
  upstream hash. The gzip uses Zopfli (=zopfli --gzip --i20= on the plain
  JavaScript); this is a build-time size optimization, not a runtime dependency.
- The runtime embedded in =server.mjs= is Brotli-compressed, with text files
  stored as text. The bundle keeps zod's English messages only (the other
  languages are never used). The generated server retains readable whitespace;
  identifier renaming and syntax minification are disabled. Review first-party
  source in =codex-plugin/src/=; all license notices remain bundled.
- Documentation screenshots are 256-colour PNGs. Run
  =python3 codex-plugin/tests/shrink-images.py docs/images/**/*.png= after
  adding new ones; =capture-readme.py= does it for the images it writes.

* Fast checks
The suites support macOS and Linux. macOS keeps temporary files behind a
symlink (=/var= to =/private/var=); =tests/realtmp.py= and the Node tests
resolve the temporary directory first, because the code under test resolves
paths and compares them.
#+begin_src sh
npm ci --prefix codex-plugin
npm run build --prefix codex-plugin
npm test --prefix codex-plugin
QUARTO= python3 -m unittest discover -s tests
#+end_src

Node 22+, Python 3.10+ and a span-aware Pandoc are required. The empty QUARTO
setting skips optional heavyweight rendering tests; converter discovery still
uses installed Pandoc/Quarto. =matsugit setup-editor= explicitly provisions the
isolated converter when needed.

* Local / preview / CI parity
#+begin_src sh
MATSUGIT_PARITY_RENDER=1 python3 -m unittest discover -s tests -p test_render_parity.py -v
#+end_src

The fast contract covers Markdown and native Org, sources and reading-note
visibility both on/off, built-in and synthetic themes, columns, tables, claims,
quotes, takeaways and literal syntax examples. It compares generated inputs and
theme/runtime files against a freshly installed native CI renderer.

The opt-in check renders real HTML through local export, the plugin preview
engine and the actual installed CI entrypoint. It verifies visible content and
embedded CSS with Quarto's bundled Pandoc, including older readers that ignore
Org BEGIN-block parameters. The test uses only synthetic content and never
publishes, pushes, authenticates, or changes an existing CI checkout.

This checks the native matsugit CI bundle, not every third-party or older private
renderer. The =topics= adapter intentionally uses the destination's own renderer;
updating the plugin cannot silently update that separate deployment.

* Browser safety

Incoming changes are now queued for explicit acceptance, not automatically
applied to the open draft. =scoped-agent-browser.py= covers one-click clean and
two-sided acceptance, a conflict opening comparison, a newer write racing the
click, neutral status, and a prompt that fits 320/390 px panels. Run it in both
the standard and Cursor-style hosts. =story-peek-browser.py= covers the temporary
full-slide view, working material below the export boundary, unsaved content,
mobile slide mode, Escape and return focus/selection/scroll.

The browser tests exercise the real built MCP workspace with temporary synthetic
files: concurrent drafts, recovery-copy failures, stale versions, selective
review, conflict choices, explicit saving, publication receipts and narrow/wide
viewports. Story tests cover subtree moves, drag/drop, keyboard reordering, title
edits, section/detail folding, explicit saves, undo and concurrent agent edits.
Layout tests cover section transitions, compact grid traversal, persistent size
preferences, empty sections, long titles, native Org and mobile/split panes.
The check test makes beginner mistakes in a draft and covers the verdict chip,
located findings, Show, a fix with Undo, the Ask AI prefill, the stale-preview
marker and where the layout picker puts a slide or part; the file is never saved.
=npm test= also runs every reported problem through the real renderer, which
must fail or misrender where the check says so and accept each fixed text.
Slide AI tests use a local mock chat host, never a real agent. They check both
messaging capabilities, selected-slide scope, Save and send, stale-draft refusal,
uncertain delivery without retry, prompt retention and unsupported-host copying.
Scoped-edit tests invoke the real agent tools while the author has an unsaved
draft, then check stale revisions and same-line conflict review. Setup-check
tests cover both host styles, narrow viewports, real diagnostics, bounded busy
states, retry and stale replies, with no installs or document writes. These are
simulated host envelopes, not acceptance tests inside the native desktop apps.
Provider status tests mock GitHub/GitLab responses; real deployment
access is not required. =.github/workflows/checks.yml= is the GitHub Actions workflow for
pushes to main, pull requests and manual dispatch. It checks dependency
advisories for all three npm lockfiles and builds complete bundled license
notices. Missing notice text fails the build, including the Story CLI graph.
History is scanned locally on the runner with a checksum-pinned Gitleaks binary;
findings are redacted and source is not sent to a scanning service. npm audit
sends dependency names/versions to the npm registry, not document contents.
This is test CI for this repository, not a deployment workflow for user documents.
No account scopes are requested or expanded by matsugit.

The workflow runs checks only. Installing a plugin never installs a repository
workflow or changes account scopes. Verify its first Actions run after release.

* Render fit and one source

=tests/test_projection.py= checks independent render paths, CLI forwarding,
reading claims/anchors, notes and preservation of the authored source.
=tests/test_preview.py= checks patch invalidation, including stable-title and
claim edits versus anchor changes. The real standalone-CI test in
=tests/test_layout.py= uses the same document projection and fit runtime.

=codex-plugin/tests/render-fit-browser.py= exercises the built workspace:
crowded text, excluded notes, Show, unchanged type and source bytes, author-chosen
breaks, title/claim patches, menu labels, reading output and narrow viewports.
Run with standard and Cursor envelopes. Fit is measured as slides are displayed;
use optional rendered lint for a whole-deck inspection. Neither is a guarantee
of good design or factual accuracy. No screenshot baseline may be updated merely
to conceal a changed layout.

* Change reliability acceptance

=history-browser.py= runs against the real MCP server: checkpoint, external
edit, backend restart, one-slide restore, Undo, paused autosave, a stale review,
document restore and explicit Save. Run it with both standard and Cursor host
envelopes. =browser-fallback-browser.py= also restores and undoes a checkpoint
through the actual loopback browser server. These are not native desktop tests.

#+begin_src sh
python3 codex-plugin/tests/history-browser.py
MATSUGIT_TEST_HOST=cursor python3 codex-plugin/tests/history-browser.py
python3 codex-plugin/tests/browser-fallback-browser.py
#+end_src

Manual release gate in native Codex and Cursor: edit a synthetic Markdown file,
change a different line externally, open Changes, restore one explicitly chosen
slide, Undo, restore again, Save, restart the plugin, and reopen the same file.
Check the draft, source and history separately. A site URL is not evidence of a
deployed revision. Confirm old pages can reconnect after upgrading; a host may
still choose to create another panel. Keep the previous plugin version available
until this gate passes. Do not delete recovery data during updates or rollback.

Downstream internal package gate: rebuild from the reviewed engine commit,
verify its manifest hashes, run setup and ZIP extraction tests, check both host
launchers and repeat the same acceptance. Do not substitute a public theme for
an internal theme or publish example documents as part of an update.

Plugin 0.25.1 overrides the exact Zod pin in =@openai/mcp-extensions= 0.2.1
with the project's patched Zod 4 dependency. See
[[https://github.com/advisories/GHSA-mrhx-c7xc-m3w5][GHSA-mrhx-c7xc-m3w5]].
The lockfile resolves 4.6.7; the minimum is 4.6.6. Remove the scoped override
when upstream accepts a patched version, after rerunning the protocol tests.
An advisory scan checks published advisories, not every possible security flaw.

The optional =MATSUGIT_ORG_PREVIEWS= browser corpus uses directories named
=md-theme-a=, =org-theme-a= and =org-theme-b=. The first two must be equivalent
Markdown/Org renders; the third tests a second theme. Keep private theme assets
and real documents outside this repository.
