#+title: matsugit product requirements

* Changed requirement: publishing references and interrupted Share (2026-11-18)

A local reference to a spreadsheet or other file outside the source project
must not prevent CI publication of the document or disclose the linked file.
An interrupted status lookup is not evidence that a push failed. Distinguish
unconfirmed delivery from a failed job and from a verified Pages deployment.

* Changed requirement: ship the VS Code editor (2026-11-17)

The Git release must provide an installable native editor, not only a parked
preview branch. Install without npm builds or automatic prerequisite downloads.
Use the existing workspace over a CustomTextEditorProvider; VS Code owns the
buffer, native saves and backups. Unreviewed external buffer changes must block
stale draft writes. Keep the Cursor/Codex adapter paths unchanged. Package work
profiles under separate extension identities without including corporate content
in the public distribution. Test in an isolated real VS Code instance.

* Changed requirement: browser editing from the plugin (2026-11-16)

Codex and Cursor panels expose an Open in browser toolbar action. It opens the
same Markdown/Org file in the existing browser editor, without publishing or
creating an export. Unsaved writing requires Save and open or Cancel; conflicts
and pending table edits must be resolved first. Saving remains version-checked.
Show the runtime machine and a fallback link; do not claim a browser opened just
because its launch was requested. Retain the plugin draft and normal external
change review when the browser subsequently saves. Do not expose a public server.

* Changed requirement: checks belong to the active output (2026-11-15)

Reading mode must not show slide-only heading, claim, takeaway, column-count,
aspect-ratio or density findings as document problems. Shared syntax, chart
and actual document-render failures remain actionable. Switching outputs
clears the other output's failed-preview notice, including when the new view
is cached. Checks never rewrite the source or weaken slide validation.

* Follow-up reports after document export (2026-11-15)

- Open document/Open slides and export-related open-link buttons reportedly do
  nothing instead of opening the browser. Investigate host navigation after the
  document-export fix; do not conflate a click/request with confirmed opening.
- A table close to a heading reportedly appears as pipe text. A synthetic table
  immediately after a heading parses correctly; one after ordinary paragraph
  text without a blank line reproduces the failure. Confirm the user's exact
  excerpt and affected view before changing parsing; preserve literal code.

* Changed requirement: independent reading exports (2026-11-15)

Document HTML/PDF exports must never invoke slide layout or fail on slide-only
heading rules. The workspace offers explicit Document PDF/HTML choices and
defaults to the active view. CLI --view and Emacs M-x matsugit-export select
the same backend path. ZIP remains both outputs; PowerPoint remains slides.
Reading PDFs include folded content. The source and unsaved draft stay intact.

* Next release: forgiving slide builds (2026-11-15)

Recoverable authoring mistakes should produce warnings and usable slides, not
abort a whole Pages build. Start with misplaced or additional H3 body headings:
interpret them safely for rendering, without rewriting the Markdown source.
Report any fallback clearly. Keep security checks and genuine rendering failures
fatal; never silently drop content or claim a broken output succeeded.
This is follow-up work, not part of the opt-in folding release.

* Changed requirement: opt-in reading disclosures (2026-11-15)

This supersedes automatic foldability introduced in 0.36.6. Unmarked document
HTML has no disclosure controls. A boolean document-collapsible YAML option
marks all reading sections; .collapsible marks a chosen heading or fenced div.
Foldability is inherited by all subsections, each initially collapsed; opening
a parent does not expand its children. Every marked element starts collapsed
on opening HTML. An explicit block can
carry a title. Add and slash completion offer a collapsible-content template.
Printing/PDF and slides retain all content; source text is never rewritten.

* Changed requirement: usable shared links (2026-11-15)

Share provides distinct Open slides/document buttons and accessible copy icons.
Copy reports success only after a clipboard API succeeds, tries a modal-safe
fallback, and selects the full URL for manual copy when the host blocks both.
HTTP internal Pages links remain supported. Copy does not save or publish.

* Changed requirement: focused reading and clear acceptance (2026-11-15)

Document mode omits slide density and measured slide-fit advice, while retaining
source errors and document preview failures. Reading sections have quiet,
keyboard-accessible disclosure buttons and start expanded; printing expands all
content. Folding never changes source. Pending acceptance has a prominent
action; an applied update offers optional inspection, not another acceptance.

* Changed requirement: one opening title (2026-11-15)

Metadata and an authored opening cover must not create duplicate title slides
by default. Explicit slide-title-page settings still win. The reading document
deduplicates a matching opening H1 or H2 without removing its anchor, claim or
body. Preview, HTML/PDF/PPTX and Pages CI use the same policy. Do not rewrite the
source or remove later headings merely because their text matches the title.

High-level requirements. README.org and docs/ describe behaviour in detail;
design.md explains how the code is organised.

* Product principle

Your next presentation starts with the notes you already have. One editable
Markdown or Org file holds titles, claims, evidence and takeaways. It renders as
themed slides and as a reading document. You control the story; the theme does
the formatting. Rendering uses no model tokens; an agent is optional.

* Who it is for

1. People who think in Markdown or Org and want slides without PowerPoint.
2. People who feel the pain of going back and forth in PowerPoint but are *not*
   technical: they can type Markdown when shown, but the syntax is unfamiliar
   and they will not read a syntax reference. Most use Cursor; others Codex.
   (Added 2026-11-10; drives the "Intuitive authoring" requirements below.)

* Requirements

** Source and rendering
- R1. One canonical source file (Markdown, Quarto Markdown or Org). No hidden
  format, sidecar or second editable copy.
- R2. The same source renders slides and a reading document with a chosen theme.
- R3. A bounded set of slide recipes composed from ordinary Markdown and a few
  semantic blocks; the theme never changes what headings mean.
- R4. Document code is data and is never executed. Themes are explicitly
  selected, trusted inputs.

** Workspace (Codex and Cursor, one shared bundle)
- R5. Source, Story and preview in one workspace; explicit Save with version
  checks, recovery, and review of external changes.
- R6. Preview never publishes. Export and publication are separate, explicit,
  reviewed actions.
- Verified scoped agent edits combine automatically only when independent of
  the current draft. Ordinary file edits require acceptance. Overlaps and
  uncertain rewrites require comparison; unsaved typing is always retained.
- Story offers a temporary full-slide preview without losing position or edits.
- A top-level export boundary keeps working material in the editor, workspace
  preview and Git, but excludes it from delivered outputs, including native CI.
- Project themes augment shared and built-in themes. Discovery and rendering
  use the same precedence; Refresh rereads configuration without losing drafts.

** Intuitive authoring (0.26, branch =intuitive-authoring=)
- R7. A newcomer never needs the syntax reference to add a slide or layout:
  layouts are picked by picture and plain name, and land in a sensible place
  wherever the cursor is.
- R8. The workspace always says whether the deck is working. Problems are
  stated in plain words, name the slide and line, say how to fix them, and offer
  a one-click fix where that is safe. Fixes edit the draft as one Undo step and
  never save.
- R9. A mistake that stops the preview is announced as such, and the stale
  preview is visibly marked. No silent staleness.
- R10. The check is honest about its limits: structure only, the renderer stays
  the authority, a clean verdict is not a reviewed deck.
- R11. The first screen shows formatted text, not markup, for Markdown files.
- R12. Agents speak in slide words to these users, get the same findings as the
  workspace (=matsugit_check=), and offer goal-shaped entry points
  (=/matsugit-new=, =/matsugit-check=, =/matsugit-help=).
- R13. None of the above changes the source format or removes a power-user
  path: Raw mode, the =/= list, Org and the CLI keep working.

** Delivery
- R14. Local export to HTML, ZIP, PDF and editable PowerPoint.
- R15. Reviewed Git publication and optional CI deployment; never automatic.

** Publishing follows the document
- R16. When a reviewed publication moves the source into the publishing
  checkout, the open workspace follows it automatically: new path shown, Save
  writes there, unsaved typing kept. No reopen step.

** Sharing without Git knowledge (0.27, branch =clearer-save-and-git=)
- R17. One =Share= button covers saving, syncing and deploying for someone who
  has a GitLab or GitHub project but knows no Git commands. It shows one state
  and one next step, in plain words.
- R18. Share saves first, shows what will be sent, and sends only on a final
  click. It never logs in, creates a project, installs a site build or changes
  access.
- R19. Share says =Live= only when the provider reports this version deployed;
  otherwise it says what it does not know.
- R20. The detailed Git sync, Publish and status views remain available.
- R21. Everything above works identically in Cursor and Codex.

** Clear state, no lost typing (0.28, branch =share-clarity-and-autosave=)
- R22. Explicit Save is the default. Opt-in autosave writes after a short pause
  with the same version check. Ambiguous external changes pause for review.
- R22a. The author and an agent can edit the same file at the same time.
  Changes on different lines combine without a prompt and without moving the
  cursor; a write made from a stale read never erases recent typing; overlapping
  changes are never guessed and never overwritten. This is the purpose of the
  save design and must hold with autosave on or off.
- R23. Share always shows its three steps and which one is next; the result of a
  site build reaches the author without reopening the dialog.
- R24. The header shows only everyday actions; the rest is in one =More= menu.

** A workspace that feels finished (0.29, branch =polish-ux-and-readme=)
- R25. The workspace opens directly on the requested file inside the chat.
  Labels, tooltips and the setup guide provide orientation; no start screen
  or instruction banner takes space away from the document.
- R26. The formatted view reads as a document, not as a code editor.
- R27. The author can always see the whole deck as a storyline (titles in
  order, not pictures of slides), where they are in it, and which slides need
  attention. The product is about the argument; thumbnails would turn it back
  into a slide sorter.
- R28. Text on a slide leads back to the same text in the editor.
- R29. The README shows the workflow and gives commands usable from a fresh
  checkout; reference detail lives in the guides.
- R30. The plain-language check is available from the command line.
- R31. Both test suites pass on macOS and Linux.

** Robustness first (0.30, branch =robustness-and-finish=)
- R32. No sequence of typing, undo, saving and another writer's edits may
  remove another writer's lines from the file or lose the author's typing
  without a review the author resolves. Covered by a seeded stress test.
- R33. Every visible, enabled control does something; a control that cannot act
  is disabled and says why.
- R34. The workspace survives a plugin restart, a read-only, deleted or moved
  file, and a second window on the same file, without losing text or writing
  anywhere unexpected.
- R35. The chrome is neutral; the deck's theme is the only colour.

** Getting back to a shared deck (0.31, branch =published-links=)
- R36. After sharing, the author can open the deck's slides, its reading
  document and its source on GitLab/GitHub in one click, from Share and from
  the =...= menu; agents can return the same links.
- R37. Share asks a project that builds only on request to build. A failure to
  ask never turns a successful push into "That did not work".
- R38. While the site rebuilds, Share reports the build step where the provider
  shows it. The project's CI owns deployment order. Share must not imply that
  documents always wait for slides, or change an independent document pipeline.
- R39. A slide that continues the previous one uses a `---` break, never a
  repeated "(continued)" title. The skill says so and Check offers the fix.

** Package size (branch =smaller-bundle=)
- R40. Keep 8 MB (8,000,000 bytes) as a secondary footprint target, not a
  correctness or feature constraint. Report size in tests; strict enforcement
  is opt-in for size-constrained distributions. Downstream plugin archives
  must measure their own expanded payload.
- R41. Size is not bought with minifying the server code: its source-module
  excerpts stay readable for review.

** First run (0.32, branch =onboarding=)
- R43. A first-time user sees the value within a minute, from the chat: one
  command or one ask opens a sample deck that teaches by being used. No
  standalone start screen; nothing appears unless the agent opens it.
- R44. With their own material, the first draft appears without an approval
  round trip, open in Story, where the storyline is edited directly.
- R45. A missing tool never looks like a problem in the deck: it is named, with
  what to install, and Check stays clear.
- R46. The first screen shows no markup: the cursor starts on the first sentence
  of the first slide, never on a block, which would hide its label.
- R47. A copy with no file (the app launcher) says it is not saved and how to
  get a deck that is kept, for as long as it is open.

** Browser fallback (0.33, branch =browser-fallback=)
- R48. When the workspace cannot appear beside the chat (no plugin, another
  agent, a terminal, or a host that fails), the same workspace opens in the
  user's browser with one command, =matsugit open [file]=, which the skill runs
  by itself. Everything works there except sending to the chat: Ask AI copies.
- R49. The browser workspace is private: this computer only, an unguessable
  address, other sites cannot reach it, and it stops when the tab is closed.
- R50. The agent keeps editing the file on disk; the open tab takes its changes
  in the same way as beside the chat.

** Claude (0.34, branch =claude-plugin=)
- R51. Claude Code users install matsugit as a plugin with two commands and get
  the skill, the slash commands and the workspace. Because Claude Code shows no
  panels, opening a deck there opens the browser workspace by itself and tells
  the user the address; no extra step for the agent or the user.
- R52. Claude Desktop shows the workspace in the conversation after one setup
  command, which changes nothing else in its configuration.
- R53. Hosts that show panels keep them: the browser is used only for a host
  known to be text-only, or when the user asks for it.

* Next steps

Reliability release (workspace 0.35.0):
- Scoped agent edits use the existing Story parser and version-checked save
  path. They reject changed saved revisions, ambiguous replacements and edits
  that alter slide boundaries. Unsaved panel drafts still use existing review.
- Read-only setup diagnostics share one report between the CLI, agent tool and
  workspace. Missing optional tools never block core readiness. No installs,
  logins, credential discovery or publication occur during a check.
- Changes brings together draft/file/push/live observations, private source
  checkpoints and recent local Git commits. These are separate observations,
  not a linear status; a draft may be newer than a verified live version.
- Restore document or an explicitly targeted slide as one undoable draft edit.
  A pre-restore checkpoint must succeed; automatic saving waits for explicit
  Save. Images and themes are not restored with source text.
- Bounded SQLite history survives process restarts and simultaneous writers;
  approved Share moves carry history, copies do not. No history lives beside
  the Markdown file. Git reads never fetch, checkout, reset or commit.
- Native-host acceptance, broader incremental rendering and release/update UX
  remain follow-up work, not claimed complete by simulated-host checks.

* Requirements that changed

- 2026-11-15, presentation exit must be discoverable without hover or a shortcut.
  Keep the Present/fullscreen entry behavior; show a persistent, labeled
  =Exit presentation= command that returns to the prior view.

- 2026-11-14, preserve the existing slide design and manual boundaries. One
  authored Markdown document remains authoritative; reading and slide outputs
  are generated independently. Actual rendered overflow is advisory in Check,
  with Show pointing to the source. Never silently split, shorten, delete or
  shrink text. A document-only render does not prepare the slide layout.
  Reading cleanup preserves wording and excludes private notes by default.
  Safe title/claim patches must preserve anchors or fall back to full rendering.

- 2026-11-12, no workspace in the chat. Was: the agent explained
  =matsugit setup-cursor= and stopped (or rendered static HTML), and the skill
  said not to create another editor or web service. Now: it opens the same
  workspace in the browser with =matsugit open=, a private local server.
  Reason: R48.

- 2026-11-10, default editor. Was: "Raw is the initial default" for the source
  pane. Now: Markdown opens in Visual; Org opens in Raw. An explicit =editor=
  option and a restored session still win. Reason: R11.
- 2026-11-10, insert button. Was: the =+= toolbar button opened the same
  keyboard completion list as typing =/=, at the cursor. Now: =Add= opens the
  layout picker and chooses the position itself; the =/= list remains for the
  keyboard. Reason: R7 (the list showed nothing with the cursor at the top of
  the file, and listed keywords with raw source).
- 2026-11-10, preview errors. Was: a failed render showed the renderer's
  message in the notice bar and left the old preview in place. Now: the notice
  restates it in slide words with =Show problems=, and the preview is marked as
  the last version that worked. Reason: R8, R9.
- 2026-11-10, header delivery controls. Was: a =Not pushed= status button, a
  Git sync icon and a Publish icon, each with its own dialog. Now: one =Share=
  button; those dialogs open from =Share > More options=. Reason: R17.
- 2026-11-10, saving. Was: nothing is written to the file until Save is
  pressed (R5 "explicit Save"). The proposed default-on autosave failed two
  stale-writer regressions. Keep explicit Save by default, offer opt-in autosave,
  and require review whenever retained historical bases disagree (R22).
- 2026-11-11, Undo after a merge. Was: Undo after a merge returned to the
  incoming file, with Redo restoring the merge. Now: Undo stops at a merge or a
  resolved review. Reason: R32 (one Undo plus Save erased lines the author had
  chosen to keep, including another writer's).
- 2026-11-11, read-only files. Was: Save replaced them. Now: refused until
  writable. Reason: R34.
- 2026-11-12, new-deck flow. Was: the agent proposed one line per slide in chat
  and waited for approval before writing. Now: it drafts straight away and opens
  Story, where the storyline is approved by editing it. Reason: R44.
- 2026-11-12, empty workspace. Was: a placeholder deck ("Slide title"). Now: the
  guided sample. Reason: R43.
- 2026-11-10, view names. Was: =Markdown= / =Render= / =Split= and =Raw= /
  =Visual=. Now: =Write= / =Preview= / =Side by side= and =Markdown= /
  =Formatted=. Tool option values are unchanged. Reason: R26.
- 2026-11-10, external edits inside saved text. Was: any incoming change that
  touched text saved earlier in the session required review. Now: accepted
  automatically when the incoming text still contains a distinctive line of
  that saved text in place; otherwise review as before. Reason: R22a (an agent
  editing the slide you just wrote is the common case).
- 2026-11-10, control names. Was: =Auto= and =Sync=. Now: =Auto-update= and
  =Follow=. Behaviour unchanged.

* 0.36.1: layout editing, position continuity and reliable delivery
- Protect container boundaries in Formatted editing; keep Raw fully editable.
- Preserve the visible passage across appearance switches.
- Honour explicit image heights rather than allocating at least 96px to every image.
- Expose per-slide Compact spacing and full runtime versions in Check setup.
- Let authors explicitly export to Downloads on the named runtime machine.
- Fitting requirements: bounded automatic fitting inside assigned layout regions; unchanged layouts
  that already fit, readable text floors, consistent regions and preview/export parity.
  Keep titles/claims fixed by default; share sizes among semantic peers within a
  slide, without allowing a dense slide to shrink the rest of the deck.

* Changed requirement: protected automatic agent updates (2026-11-15)
- Evolve acceptance-only updates for verified scoped edits, not arbitrary writers.
- Reconcile against the current draft, checkpoint first, and revalidate both
  draft and incoming file before applying. Typing during merge triggers retry.
- Autosave affects persistence only. Off retains the combined unsaved draft;
  on saves only through the existing version-checked save after reconciliation.
- Agent updates are isolated undo steps. Overlaps open comparison; pending
  tables, restores, Redo and uncertain history do not get automatic application.
- Keep existing stale whole-file rewrite protection and unknown-writer prompts.

* Automatic fitting implementation
- Shared browser runtime: bounded peer sizing after spacing reduction.
- Preserve breathing room: gradual margin reduction capped at 10%, then restore
  as much spacing as possible after text fitting. Already-fitting slides unchanged.
- Fixed semantic hierarchy, explicit opt-out, no source mutations or hidden overflow.
- Validate fit/reset/idempotence and real HTML/PDF; PowerPoint remains separate.

* Export Runtime Reliability (2026-11-15)
- PDF/diagram fallback must launch at most one export interpreter. Missing
  dependencies in that interpreter must fail with repair instructions, never
  recursively create workers or exhaust a shared server.
- =setup-export= must repair an existing virtual environment after an OS
  Python upgrade, retaining hash-locked dependencies.
** Changed Requirements
- Existence of the export interpreter was previously treated as proof that
  its environment remained usable. It is not; refresh it during explicit
  setup and bound fallback independently of dependency health.
